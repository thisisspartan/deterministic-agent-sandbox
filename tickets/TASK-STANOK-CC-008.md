# TASK-STANOK-CC-008 — input: удержание = движение (замена toggle-схемы)

## Контекст

Сейчас `src/input.js` реализует **toggle-управление**: нажатие клавиши включает
действие, повторное нажатие той же клавиши — выключает. Оператор подтвердил баг:
игрок продолжает двигаться после отпускания клавиши (потому что «отпускание»
терминалом не шлётся, а остановить движение можно только повторным нажатием).

Решение оператора (грилл 2026-08-26): **удержание = движение**.
Нажал клавишу — действие включено; отпустил — выключено.

## Как это работает в терминале (важно)

Терминал в raw mode **не шлёт keyup-событий**. Единственный наблюдаемый сигнал
«клавиша зажатая» — **автоповтор**: пока клавиша зажата, терминал шлёт повторные
коды (примерно каждые 30–50 мс после начальной задержки). Когда клавишу отпускают,
повторы прекращаются.

Следовательно «отпущено» — это **отсутствие новых кодов той же клавиши** в течение
окна, превышающего интервал автоповтора.

## Требования

1. **Включение:** первое нажатие клавиши движения (W/S/A/D/Q/E, стрелки) включает
   соответствующее действие — как сейчас.
2. **Удержание:** пока приходят повторные коды той же клавиши (автоповтор),
   действие остаётся включённым. Повторы НЕ должны сбрасывать/переключать действие
   (текущий toggle-фильтр «повтор < 100 мс игнорируется» заменяется этой семантикой).
3. **Отпускание:** если в течение **TIMEOUT_MS** (константа, ~150 мс; подобрать
   так, чтобы было больше максимального интервала автоповтора и меньше, чем
   минимальное время осмысленного отпускания) не пришёл ни один код этой клавиши —
   действие выключается. Реализовать через `setTimeout`/`clearTimeout` на каждое
   включённое действие (или единый механизм — на выбор станка).
4. **Переключение между клавишами группы:** нажатие другой клавиши из той же группы
   эксклюзивности (например, `W` → `S`) переключает действие на новую, старое
   действие выключается (включая снятие его таймера отпускания). Текущая логика
   групповой эксклюзивности (`GROUPS`) сохраняется.
5. **Esc:** без изменений — sticky, `quit: true`, не участвует в группах,
   не имеет таймера отпускания.
6. **Стрелки** (ArrowUp/Down/Left/Right) — та же схема «удержание = движение»,
   дублируют W/S/A/D (ArrowUp = forward и т.д., маппинг `KEY_TO_ACTION` без изменений).
7. **`createInputHandler`** возвращает `{stop()}` как сейчас; `stop()` должен
   снимать все слушатели И очищать все живые таймеры отпускания (чтобы игра не
   «доживала» движение после выхода).
8. **Чистые части** (`KEY_TO_ACTION`, `parseKeySequence`, `applyKey` и любые новые
   чистые хелперы) — без `process`/`Date`/side effects, юнит-тестируемы без TTY.
   Таймеры и stdin — только внутри `createInputHandler`.

## Инварианты

- После отпускания ВСЕХ клавиш состояние должно стать `{forward:false, back:false,
  left:false, right:false, strafeLeft:false, strafeRight:false, quit:false}`
  (кроме sticky `quit`).
- Движение в game loop (`main.js`) остаётся real-time: `updatePlayer` вызывается
  каждый тик с текущим `inputState`; изменения в `main.js` не требуются, если
  контракт `createInputHandler(onStateChange)` не меняется.
- Никаких рывков: включение — мгновенно на первом коде, выключение — по таймауту.

## Критерии приёмки

1. Юнит-тесты чистых частей проходят (TDD: сначала красный, потом зелёный).
2. Поведение «нажал → едет, отпустил → стоит» покрыто тестами в той мере, в какой
   это тестируемо без TTY (чистая логика состояния + таймеры — через инъекцию
   времени/таймеров или вынесение чистой функции «state + события → next state»).
3. `stop()` не оставляет живых таймеров (проверяемо: после `stop()` процесс
   завершается, не зависая на таймерах).
4. Esc — выход, терминал восстановлен (регрессия).
5. Все существующие тесты (`tests/*.test.js`) проходят без изменений семантики
   чистых частей, которые не затронуты тикетом.

## Границы

- Не менять `maze.js`, `raycaster.js`, `player.js`, `main.js`, если контракт
  `createInputHandler` не меняется.
- Не вводить внешних зависимостей.
- Не менять рендер, HUD, экран победы.
