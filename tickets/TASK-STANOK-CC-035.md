# TASK-STANOK-CC-035 — fire: жизненный цикл огня (горение → догорание → угли → разгорание)

## Контекст

Модуль `src/fire/` (тикеты 030–034): живое пламя, тёмный камин, глифы плотности —
видно в любом терминале. НО огонь горит **вечно на одной интенсивности** —
оператору нужен живой цикл: огонь **горит, догорает, тлеет углями, и снова
разгорается** — цикл повторяется, пока пользователь не выключит (q/ESC).

Сейчас `step()` в `fire.js` — стационарный процесс: источник всегда на
BASE_FLOOR + flicker, пламя в steady-state. Никакой динамики «догорания».

Цель: детерминированный (PRNG) жизненный цикл огня внутри `step()`, без
изменения API и без правок `ui.js`/`main.js`.

## Задача

### L1. Состояния цикла (физика, fire.js)
Добавь в state машину состояний (по step'ам, не по времени — 30 FPS):

1. **BURN** (горение): как сейчас — источник на BASE_FLOOR + flicker, пламя
   полное. Длительность: `BURN_STEPS` (подбери ~1200–1800 step'ов = 40–60 с).
2. **DIE** (догорание): источник **постепенно слабеет** — множитель источника
   плавно падает с 1.0 до ~0.15 за `DIE_STEPS` (~300–450 step'ов). Пламя
   сжимается к основанию, верх гаснет первым (естественно — из-за decay).
3. **EMBER** (угли): источник ≈ 0, но в основании окна (1–2 ряда над plinth)
   тлеют **угли**: несколько ячеек с heat ~0.1–0.3, медленно мерцающих
   (flicker с малой амплитудой, период длиннее, чем у пламени). Длительность:
   `EMBER_STEPS` (~150–300 step'ов).
4. **REKINDLE** (разгорание): источник растёт с ~0 до 1.0 за `REKINDLE_STEPS`
   (~150–300 step'ов) — пламя «вспыхивает» и возвращается в BURN.

После REKINDLE → BURN → цикл зациклен. Переходы только по счётчику step'ов
(детерминированно), порядок фиксирован: BURN → DIE → EMBER → REKINDLE → BURN.

### L2. Детерминизм
- Всё на PRNG (mulberry32, тот же seed) — никаких Date.now/Math.random.
- Тот же seed → идентичная последовательность кадров, включая фазы цикла.
- Угли: позиции тлеющих ячеек — фиксированный подмножество ячеек источника
  (через PRNG при входе в EMBER), мерцание — PRNG.

### L3. Не ломать
- API: `createFire(opts)`, `render(state, width)`, `colorIndex`, `mulberry32` —
  сигнатуры не менять. `ui.js`, `main.js` — **не трогать** (цикл живёт в
  `step()` fire.js).
- Рендер не меняется: глифы плотности, рамка, искры — как в 034.
- Искры: в EMBER/REKINDLE искр нет или мало (источник слабый) — логично из
  физики, не хардкодом.
- Non-TTY режим main.js (10 кадров) — работает (10 кадров = начало BURN).
- Существующие тесты (fire/render/liveness/glyphs/ui) — не ломать.

## Тесты (TDD, `tests/fire/`)

Новые тесты (новый `tests/fire/lifecycle.test.js`):

1. **Цикл существует**: прогнать ≥ (BURN+DIE+EMBER+REKINDLE) step'ов;
   max(heat) по окну обязан пройти через: высокий уровень (BURN, >0.7) →
   падение (DIE) → низкий уровень (EMBER, <0.35) → рост (REKINDLE) → высокий
   снова. Зафиксировать пороги и длительности константами в тесте.
2. **Догорание монотонно-убывающее**: в фазе DIE max(heat) окна не растёт
   в среднем (сглаженное по 30 step'ов значение не увеличивается).
3. **Угли**: в фазе EMBER в основании окна есть ≥3 ячейки с heat в [0.05..0.4],
   и их heat меняется между кадрами (мерцание), но max(heat) окна < 0.4.
4. **Разгорание**: в фазе REKINDLE max(heat) окна растёт от <0.4 до >0.6.
5. **Детерминизм цикла**: два createFire с одним seed → прогнать полный цикл →
   heat идентичны на каждом переходе фаз.
6. **Длительность BURN**: фаза BURN длится ≥ 1000 step'ов (огонь горит долго,
   не мигает между фазами).
7. Существующие тесты (fire/render/liveness/glyphs/ui) — не ломать.

Запуск: `bash scripts/run.sh test tests/fire/<file>.test.js` (single-file).
