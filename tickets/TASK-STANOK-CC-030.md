# TASK-STANOK-CC-030 — fire: цветное пламя в консоли (бесконечная анимация костра)

## Задача

Сделать консольную программу **fire**: бесконечная анимация горящего костра —
цветное пламя полыхает, мерцает, летят искры. Работает вечно, пока пользователь
не нажмёт выход (`q` / `ESC` / `Ctrl+C`).

## Зона

Новые файлы: `src/fire/`, `tests/fire/`, `docs/fire.md`.
**НЕ трогать** другие модули (`tetris/`, `stats/`, `grid.js` и т.д.) — только
читать как референс. Паттерн UI-модуля уже есть: `src/tetris/ui.js` (raw mode,
`parseKeys`, ESC-последовательности, split-чунки) и `src/tetris/main.js`
(lifecycle, SIGINT). Читай их перед началом.

## Требования

### F1. Физика пламени — `src/fire/fire.js` (чистая логика, без io)
- Сетка `W×H` (дефолт 80×24, настраивается через opts).
- Поле температуры `heat[y][x] ∈ [0..1]`.
- Источник тепла — нижний ряд: базовая температура ~1.0 с фликером (шум).
- Шаг симуляции (снизу вверх): `heat[y][x] = avg(heat[y+1][x-1..x+1]) * decay + noise*sparkle`,
  `decay ≈ 0.85..0.92`.
- Детерминизм: PRNG инжектируется (`opts.rng`, дефолт `mulberry32(seed)` —
  написать свой маленький PRNG, без зависимостей). Один seed → идентичные кадры.
- Искры: N частиц `{x, y, vy, life}`; поднимаются, затухают, возрождаются у основания.
- Публичный API: `createFire(opts)` → `{ step(), heat, sparks, W, H }` (или эквивалент,
  но чистый и тестируемый).

### F2. Рендер (ANSI) — `src/fire/render.js` или внутри fire.js
- Палитра по температуре (256-цветные коды `\x1b[38;5;Nm`): 0 → пусто; затем
  тёмно-красный → красный → оранжевый → жёлтый → белый (горячее ядро).
- `render(state) → string` — ЧИСТАЯ функция: кадр одним строковым блоком
  (курсор в начало, строки, очистка хвоста).
- Искры рендерятся поверх пламени яркими пикселями.

### F3. UI-цикл — `src/fire/ui.js`
- `attach(io, opts)` — паттерн как в `src/tetris/ui.js`: raw mode, парсинг
  клавиш, таймер 30 FPS (настраивается), полный перерисовочный кадр.
- Альтернативный экран (`\x1b[?1049h`), скрытие курсора при старте;
  восстановление (курсор + выход из alt-экрана) при остановке — ВСЕГДА,
  включая выход по клавише и по ошибке.
- Выход: `q`, `Q`, `ESC`, `Ctrl+C` → `stop()` → чистый выход.

### F4. Entry point — `src/fire/main.js`
- `node src/fire/main.js` — интерактивный режим (TTY).
- **Non-TTY guard**: если `stdout` не TTY → отрендерить фиксированное число
  кадров (например 10) в stdout и `exit(0)`. Критично для CI/пробок:
  программа не должна вешаться без терминала.

### F5. Гигиена
- Никаких внешних зависимостей.
- `docs/fire.md`: запуск, управление (клавиши выхода), параметры, палитра.

## Тесты (TDD)

- `tests/fire/fire.test.js` — физика: нагрев снизу вверх, затухание вверх,
  детерминизм по seed (2 прогона с одним seed → идентичные кадры),
  палитра (температура → цвет), искры (рождение/смерть/возрождение).
- `tests/fire/ui.test.js` — mock io + mock timers (как в `tests/tetris/ui.test.js`):
  start/stop, выход по `q`/`ESC`/`Ctrl+C`, восстановление терминала при stop.
- Запуск тестов: `node --test tests/fire/fire.test.js` и
  `node --test tests/fire/ui.test.js` (single-file, НЕ directory-mode).

## Критерии приёмки

1. `node --test tests/fire/fire.test.js` — зелёный.
2. `node --test tests/fire/ui.test.js` — зелёный.
3. `node src/fire/main.js` в non-TTY: печатает кадры и выходит с кодом 0

4. `docs/fire.md` создан.
5. Артефакты закоммичены (коммит делает станок по своему протоколу).
