# TASK-STANOK-CC-028 — tetris ui: DAS не сбрасывается при отпускании стрелки (рефикс 025)

## Контекст

Оператор: «управление в тетрисе не пофикшено». Факт (проверен супервайзером):
тикeт 025 добавил `handleKeyUp` в `src/tetris/ui.js` (~L283-293) и экспортировал его
в return-объект `attach`, НО:

1. `parseKeys` (ui.js ~L150) НЕ различает key-down от key-up: стрелка шлёт те же
   3 байта (`\x1b[C` и т.д.) и при нажатии, и при отпускании. `onKey` → `handleKey`
   обрабатывает оба события одинаково (как нажатие).
2. `handleKeyUp` **нигде не вызывается**: ни из `onKey`, ни из `main.js`. Фикс 025
   мёртвый код — DAS-повтор (`dasStep`) после отпускания стрелки продолжает двигать
   фигуру, пока не нажата другая клавиша или `stop()`.

Задача: сделать сброс DAS при отпускании стрелки **реально работающим**.

Зона: `src/tetris/ui.js`, `src/tetris/main.js` (только подключение key-up, если
нужно), `tests/tetris/ui.test.js`. НЕ менять: `pieces.js`, `board.js`, `bag.js`,
`game.js` и их тесты. Не менять публичный API `attach(io, game, opts)` (возвращаемый
объект может получить новые поля — это допустимо; сигнатуру `attach` — нет).

## Что сделать

1. **Определи факт поведения терминала** (не на веру): в raw-mode Linux-терминал
   (xterm/VT100-совместимый) НЕ шлёт key-up для стрелок — отпускание = те же байты.
   Проверь по факту (docs/комментарий в коде + тест), какой вариант применим:
   - **Вариант A (рекомендуемый, если терминал не шлёт key-up):** ключевая
     проблема — `handleKey('left'/'right')` при ПОВТОРНОМ событии той же стрелки
     сбрасывает `heldSince` и `repeatsFired` (ui.js L212-227), что и есть «нажатие
     снова». Но при отпускании байты те же → DAS не остановить. Решение:
     **DAS-таймаут** — если с последнего события стрелки прошло >N ms (например
     200ms, константа `KEY_UP_TIMEOUT`), считать клавишу отпущенной: в `dasStep`
     (или `frame`) при `now() - lastArrowEventT > KEY_UP_TIMEOUT` → `heldDir = 0`.
     Это эмулирует key-up по тишине и работает на ЛЮБОМ терминале без изменения
     байт-протокола. Нормальное удержание (терминал шлёт повторные key-down при
     автоповторе ОС/терминала) не должно сбрасывать DAS: повтор того же направления
     НЕ обновляет `lastArrowEventT` только если это тот же «залп» — проще:
     `lastArrowEventT` обновляется КАЖДЫМ событием стрелки, а таймаут 200ms больше
     любого интервала автоповтора терминала (обычно 30-80ms) — уточни по факту и
     задокументируй выбор в `docs/tetris.md`.
   - **Вариант B:** если установишь, что конкретный терминал/PTY реально шлёт
     key-up (например, отдельная последовательность) — парси её в `parseKeys` и
     зови `handleKeyUp`. Только если есть доказательство; не выдумывай протокол.
2. **`handleKeyUp` оставить** (он корректен) и подключить: в варианте A — как
   публичный хук для драйверов, знающих key-up (как сейчас), плюс новый
   таймаут-механизм внутри `attach`. В варианте B — из `onKey`.
3. **Тесты ПЕРВЫМ (TDD)** в `tests/tetris/ui.test.js` (mock game + mock io +
   injectable `now()`, как в существующих тестах):
   - Тест 1 (красная фаза): нажал left → отпустил (в варианте A: тишина >
     KEY_UP_TIMEOUT без новых событий) → `game.move(-1)` НЕ вызывается после
     отпускания. До фикса FAIL (DAS продолжает), после PASS.
   - Тест 2: удержание (повторные события left с интервалом < KEY_UP_TIMEOUT) →
     DAS-повторы идут (регрессия: не сломать автоповтор).
   - Тест 3: нажал left, отпустил, нажал right → движение только вправо.
   - Существующие 19 тестов ui + 14 game — не ломать.

## Требования

- Фикс в `ui.js` (таймаут-сброс DAS и/или подключение key-up). `main.js` — только
  если нужно передать key-up-драйверу (вариант B); иначе не трогать.
- Константы (KEY_UP_TIMEOUT и т.п.) — в `ui.js` рядом с DAS_DELAY/ARR, значения
  обоснованы в комментарии.
- `docs/tetris.md` — раздел «Управление»: фактическое поведение после фикса
  (DAS сбрасывается при отпускании/тишине; варианты A/B — какой применён и почему).
- Не менять `game.*` API, `pieces.js`, `board.js`, `bag.js`.
