# TASK-STANOK-CC-038 — fire: причина остановки + защита от чужих ESC-последовательностей

## Контекст
Пользователь видит: огонь живёт ~1 секунду и останавливается сам, хотя останавливать
должен только он (q/Q/ESC/Ctrl+C). Во всех наших PTY-тестах (голый PTY, zsh -ic,
mock-io) цикл кадров работает бесконечно — процесс живёт, пока не придёт сигнал/клавиша.
В терминале пользователя p10k показывает статус «INT ✘» (процесс убит SIGINT, exit 130)
через ~1 с. Причина не воспроизводится у нас → нужно (а) сделать причину остановки
ВИДИМОЙ для пользователя, (б) убрать ложные выходы по ESC-байту внутри чужих
escape-последовательностей (стрелки, F-клавиши, bracketed paste — всё это содержит 0x1b).

## Что сделать

### 1. `src/fire/ui.js` — точное распознавание клавиш + причина выхода
Сейчас `onKey` выходит, если чанк СОДЕРЖИТ 0x03/0x71/0x51/0x1b (`buf.includes(...)`) —
любая escape-последовательность (стрелка = ESC [ A) убивает анимацию.

Новое поведение:
- Разобрать чанк на последовательности. Выход ТОЛЬКО если:
  - байт 0x03 (Ctrl+C) — reason `'ctrl-c'`;
  - одиночный байт 0x71 (`q`) — reason `'q'`;
  - одиночный байт 0x51 (`Q`) — reason `'Q'`;
  - ОДИНОЧНЫЙ ESC: чанк ровно `[0x1b]` (длина 1) — reason `'esc'`.
    ESC, за которым идут другие байты (стрелки, F-клавиши, CSI-последовательности,
    bracketed paste) — ИГНОРИРОВАТЬ полностью, не выходить.
- `onQuit` теперь принимает аргумент: `onQuit(reason)`, reason — одна из
  `'ctrl-c' | 'q' | 'Q' | 'esc'`.
- `stop()` — без изменений в поведении (restore терминала всегда).

### 2. `src/fire/main.js` — видимая причина остановки
- `onQuit: (reason) => { process.stderr.write('fire: остановлено (' + reason + ')\n'); process.exit(0); }`
  (stderr — чтобы сообщение попало на основной экран ПОСЛЕ выхода из alt screen,
  который делает `app.stop()` в ui.js до вызова onQuit).
- SIGINT-хендлер: `app.stop(); process.stderr.write('fire: остановлено (SIGINT)\n'); process.exit(130);`
- SIGTERM-хендлер: `app.stop(); process.stderr.write('fire: остановлено (SIGTERM)\n'); process.exit(0);`

### 3. Тесты — `tests/fire/ui.test.js` (права на правку — у tester-субагента)
Добавить тесты (mock io, как в существующих):
- U1: чанк `[0x1b, 0x5b, 0x41]` (стрелка вверх) — НЕ выход: цикл кадров продолжается
  (через ~200 мс нарисован >=1 кадр, stop не вызван).
- U2: чанк `[0x1b]` (одиночный ESC) — выход, onQuit вызван с `'esc'`.
- U3: чанк `[0x71]` — onQuit `'q'`; чанк `[0x03]` — onQuit `'ctrl-c'`; чанк `[0x51]` — onQuit `'Q'`.
- U4: после выхода терминал восстановлен (setRawMode(false) вызван) — как в старых тестах.

### 4. `docs/fire.md`
- Раздел управления: q/Q/Ctrl+C/одиночный ESC — выход; другие escape-последовательности
  игнорируются. При остановке на stderr печатается причина:
  `fire: остановлено (<reason|SIGINT|SIGTERM>)`.

## Критерии приёмки
- A1. Стрелки/F-клавиши/CSI-последовательности НЕ останавливают анимацию (тест U1).
- A2. onQuit(reason) с правильным reason для q/Q/ESC/Ctrl+C (тесты U2–U3).
- A3. main.js печатает `fire: остановлено (...)` на stderr при любом пути выхода
  (ключ, SIGINT, SIGTERM) и exit-коды: ключ → 0, SIGINT → 130, SIGTERM → 0.
- A4. `node --test` по всем `tests/fire/*.test.js` — PASS.
- A5. Smoke: `bash scripts/run.sh smoke src/fire/main.js` — не падает.
