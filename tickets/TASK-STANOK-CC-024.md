# TASK-STANOK-CC-024 — clamp01: clamp/lerp/invLerp (smoke-тикeт)

## Контекст

Тестовый (smoke) тикет для проверки конвейера станка после правок на скорость
(budget-гейт, retry-наследование, cloud FAIL-only). Создаёт НОВЫЙ модуль
`src/clamp01.js` с чистыми функциями. Не связан с игровым кодом; НЕ трогать
существующие модули (`src/clamp.js`, `src/lerp.js`, `src/vec2.js`, `src/vec3.js`,
`src/dist.js`, `src/mat.js`, `src/tetris/*` и все их тесты — не менять).

Цель прогона: одна чистая попытка (CLEAN-FIRST), без ретраев. Тикет намеренно
простой и самодостаточный — если прогон уйдёт в FAIL/ретрай, это сигнал, что
правки на скорость сломали конвейер, а не тикет.

## Требования

Модуль `src/clamp01.js` (CommonJS, `module.exports`) экспортирует:

1. `clamp(v, lo, hi)` — ограничение значения диапазоном:
   `Math.min(hi, Math.max(lo, v))`.
   - `lo > hi` — `RangeError` с сообщением `"lo > hi"`.
2. `lerp(a, b, t)` — линейная интерполяция: `a + (b - a) * t`.
   (t НЕ клампится — экстраполяция допустима.)
3. `invLerp(a, b, v)` — обратная интерполяция: `(v - a) / (b - a)`.
   - `a === b` — `RangeError` с сообщением `"a === b"`.

Валидация аргументов (для всех функций):
- каждый аргумент — конечное число (`Number.isFinite`); нечисло/`NaN`/`Infinity`
  — `TypeError` с именем аргумента в сообщении (`"v"` / `"lo"` / `"hi"` / `"a"` / `"b"` / `"t"`).

## Инварианты

- `clamp(5, 0, 10)` → `5`; `clamp(-1, 0, 10)` → `0`; `clamp(11, 0, 10)` → `10`.
- `lerp(0, 10, 0.5)` → `5`; `lerp(10, 0, 0.5)` → `5`; `lerp(0, 10, 0)` → `0`; `lerp(0, 10, 1)` → `10`.
- `invLerp(0, 10, 5)` → `0.5`; `invLerp(0, 10, 0)` → `0`; `invLerp(0, 10, 10)` → `1`.
- `lerp(a, b, invLerp(a, b, v)) === v` (для `a !== b`, `v` в диапазоне).
- Все функции чистые и детерминированные: без `process`, `Date`, side effects.
