# TASK-STANOK-CC-033 — fire: живое пламя + тёмный камин (визуальный дефект)

## Контекст

Модуль `src/fire/` (тикеты 030/031/032): физика + рендер «камин» + UI. Тесты
зелёные, НО визуально пламя мёртвое и тонет в стене. Зафиксировано замером
(non-TTY, node, seed=42, W=80 H=24):

1. **Кирпичи светлые** (ANSI 236–238) — весь экран яркая стена, пламя не видно.
   Тикет 032 допускал «236–239» — это была ошибка спеки; теперь запрещено.
2. **Пламя статичное**: средняя поcell-изменённость между кадрами, снятыми
   через 60 step'ов (2 с), = 0.033 — живёт только глобальное «дыхание».
   Причина: decay=0.88 гасит шум за ~6 рядов, а источник — гладкий косинус
   без турбулентности.
3. **Пламя короткое**: heat>0.3 поднимается на 6 из 20 рядов окна (30%).

Цель: огонь, который **горит и полыхает** — видно движение по кадрам, пламя
достигает ≥60% высоты окна, камин тёмный и пламя на нём контрастно.

## Задача

### F1. Тёмная рамка (render, fire.js)
- Цвета кирпичей ТОЛЬКО из {24, 25, 26, 27, 58}. Никаких 236–239.
- Тёмный фон окна (233–235) — сохранить.
- Символы ▓ █ ▒ — сохранить. Рамка статична.

### F2. Живой источник (физика, fire.js)
- Источник НЕ должен быть гладким косинусом: добавить **per-cell flicker** —
  каждая ячейка источника каждый step получает собственный шум, например
  `b[x] = mask[x] * (BASE_FLOOR + flicker) * breath`, где flicker ~
  `(-0.25 + 0.5 * rng())` (амплитуду подбери так, чтобы max-min по ряду
  источника был ≥ 0.3).
- Итог: по ряду источника max|b[x]-b[x-1]| ≥ 0.15 (резкие переходы, не косинус).

### F3. Пламя доходит до верха окна (физика, fire.js)
- Подними decay в диапазон 0.93–0.96 (или эквивалент: слабее затухание /
  добавь вертикальную диффузию) так, чтобы **heat>0.3 поднимался на ≥ 12 рядов
  от основания** (окно = H − lintel − plinth = 20 рядов при H=24).
- Форма языка (сужение кверху, taper) сохранить; верх пламени — тлеющий
  тёмно-красный (160–196), не белый.

### F4. Живость (квантовый критерий)
- Между двумя кадрами, снятыми через 30 step'ов, средняя |Δheat| по ячейкам,
  где max(heat_a, heat_b) > 0.1, должна быть **≥ 0.05** (сейчас 0.033 — и то
  только за счёт дыхания; после F2+F3 будет за счёт турбулентности).
- Детерминизм сохранить: тот же seed → идентичные кадры (PRNG, никаких
  Date.now/Math.random в step).

### F5. Не ломать
- API: `createFire(opts)`, `render(state, width)`, `colorIndex`, `mulberry32`
  — сигнатуры не менять. `ui.js`, `main.js` — не трогать.
- Искры — как есть (центр зоны, respawn).
- Non-TTY режим main.js (10 кадров) — работает.

## Тесты (TDD, `tests/fire/`)

Новые тесты (в `fire.test.js` или новый `tests/fire/liveness.test.js`):

1. **Тёмные кирпичи**: отрендерить кадр (seed фиксированный); разобрать ANSI
   кадра; в области рамки (первый/последний ряд, первые/последние 2 колонки)
   ВСЕ цвета из {24,25,26,27,58}; цвета 236–239 отсутствуют во всём кадре.
2. **Турбулентность источника**: после 10 step'ов по ряду base
   max|b[x]-b[x-1]| ≥ 0.15.
3. **Высота пламени**: после 30 step'ов существует ряд y < base−11 с
   max(heat[y]) > 0.3.
4. **Живость**: снять heat A после 10 step'ов, B после ещё 30 step'ов;
   mean(|A[y][x]-B[y][x]|) по ячейкам где max>0.1 ≥ 0.05.
5. **Детерминизм**: два createFire с одним seed → 30 step'ов → heat идентичны
   (как есть, не ломать).
6. Существующие тесты (fire/render/ui) — не ломать.
