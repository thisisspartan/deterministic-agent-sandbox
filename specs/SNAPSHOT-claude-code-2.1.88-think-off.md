## 2. Что делает каждая правка

### `source/src/utils/messages.ts` (+35) — ядро патча
В `normalizeMessagesForAPI` (перед отправкой) инжектится `<|think_off|>` как
дополнительный text-блок в user-сообщение — **только** если:
- в сообщении есть `tool_result`-блоки (это ход ПОСЛЕ выполнения инструмента), И
- среди них нет `is_error: true`, И
- в контенте ещё нет `<|think_off|>`/`<|think_on|>` (идемпотентность).

Условия сохранены намеренно:
- планирующий ход (первый, до любых tool_result) — думание ВКЛЮЧЕНО;
- ходы после ошибки инструмента — думание ВКЛЮЧЕНО (нужно понять, что сломалось);
- обычные tool-result ходы — думание ВЫКЛЮЧЕНО (машинальный round-trip).

Шаблон Qwen (`ns_state.thinking=false` по `<|think_off|>`) соблюдается; маркер
срезается при повторной нормализации.

### `source/src/services/compact/compact.ts` (+1)
В system prompt стрим-суммаризатора компакции добавлен `<|think_off|>`
(плюс уже стоящий `thinkingConfig: {type:"disabled"}`). Компакция — чисто
механический пересказ; думание там — чистый расход токенов.

### `source/src/services/compact/prompt.ts` (+4/-1)
`NO_TOOLS_PREAMBLE` («CRITICAL: Respond with TEXT ONLY…») получает ведущий
`<|think_off|>` — ходы, где от модели ждут только текст (конец раунда, no-tools),
не тратят окно на думание.

### `cli.js` (+12/-4)
Тот же патч, скомпилированный в shipped-бандл: 5× `<|think_off|>` (+1 `<|think_on|>`
для симметрии в префиксе), `thinkingConfig:{type:"disabled"}` для суммаризатора,
замена одного `thinkingConfig` в компакции. Это результат сборки исходников в cli.js,
а не отдельная логика.

## 3. Оценка

- **Когерентно**: все четыре файла — один сценарий «думание только там, где нужно».
- **Хирургично**: +47/−5 строк, не трогает протокол, кэш, инструменты, hooks.
- **Низкий риск**: маркер инжектится только на tool-result ходах без ошибок;
  идемпотентность защищает от дублей.
- **Соответствует леверам**: это «невидимый» рычаг (модель не читает сам рычаг,
  но её поведение меняется). Не конфликтует с видимыми леверами
  (reasoning_effort в шаблоне, правило 0 в CLAUDE.md).
- **Ожидаемый эффект на станке** (Qwen3.8-27B-MTP, 1 слот): меньше токенов на
  tool-ходах → меньше вероятность обрезки EOS/незакрытого tool_use, быстрее
  round-trip, тот же результат на планировании/ошибках.
- **Риск, на который стоит смотреть**: если модель при выключенном думании начнёт
  хуже осмыслять результат инструмента перед следующим вызовом — заметно на
  многошаговых TDD-тикетах. Это проверяется прогоном, а не статически.

**Вердикт: правки обоснованы, риск низкий. Держать как срез. Деплой — отдельное
решение оператора** (рабочий бинарь 2.1.221, тюнинг 2.1.88).

## 7. РАЗГАДКА (2026-08-26, инструментальное расследование): патч ЖИВОЙ и РАБОТАЕТ,
но станок его НЕ ИСПОЛЬЗУЕТ

Обе гипотезы §6 закрыты эмпирикой. Root cause — **станок гоняет ДРУГОЙ бинарь claude**,
без патча.

### 7.1 Что проверили (всё на снапшоте cli.js 2.1.88, hash 431381e8, и живым прогоном)

1. **В бандле ОДНА normalize-функция** — `bP(q,K=[])`. Инъекция `<|think_off|>`
   (идемпотентный маркер) — только в ней (offset 9709964). Никакой «второй normalize»,
   которая обходит патч, НЕТ.
2. **SDK-путь вызывает bP**: `YFK` (главный query-генератор, `querySource==="sdk"`)
   делает `g3("query_message_normalization_start"); let V=bP(q,X); ...`. Пост-обработка
   (O77/n0K/KZK/_ZK/aSY/eSY/lSY/nSY) НЕ вырезает text-блок с маркером — доходит до wire.
3. **Патченый 2.1.88 реально шлёт маркер**: локальный логирующий прокси вставили между
   `claude -p` и сервером; на tool_result-ходу в user-сообщении виден
   `TEXT-BLOCK: '<|think_off|>'` (`kinds=['user:text','assistant:thinking,tool_use','user:text,tool_result']`).
4. **Сервер чтит маркер в точной позиции патча** (прямые /v1/messages, 4 теста):
   - TEST1 control user: `<think>` есть → думает.
   - TEST2 `<|think_off|>` в тексте: `<think>` НЕТ → не думает.
   - TEST3 [tool_result, затем `<|think_off|>`]: `<think>` НЕТ → позиция патча работает.
   - TEST4 tool_result без маркера: `<think>` есть → базовый уровень думает.
   Шаблон `/data/models/chat_template.jinja` (qwen3.8-froggeric-v22.1) в пре-пасе сканит
   ВСЕ system/user/developer сообщения на маркеры (`<|think_off|>`→`ns_state.thinking=false`,
   `<|think_on|>`→true); позиция внутри content-массива неважна.

### 7.2 Root cause: станок спавнит bundled claude 2.1.233, а не патченый 2.1.88

`stanok-sdk-probe.py` использует `claude_agent_sdk` с `SubprocessCLITransport`. В
`subprocess_cli.py::_find_cli()` приоритет: **bundled** (`<pkg>/_bundled/claude`) → `which("claude")`.
В станке `_bundled/claude` СУЩЕСТВУЕТ (324MB, 2026-08-15) → `options` НЕ задают `cli_path`
(проверено, строки 678-692) → станок всегда запускает **bundled 2.1.233**, где
`think_off` = 0 вхождений. Патченый 2.1.88 (`~/.npm-global/bin/claude` → symlink на
`~/git/claude-code-2.1.88/cli.js`) в станке не участвует.

Поэтому: думание на каждом шаге, маркеров в прогонах нет, ускорения нет — патч физически
не исполнялся. Сравнение «рабочий бинарь = 2.1.88 = этот же cli.js (cmp идентичен)» было
сделано для shell-бинаря, а не для того, что поднимает SDK.

### 7.3 Компакция

В станке компакция тоже выполняется bundled 2.1.233 (нативный `querySource:"compact"` +
system prompt «You are a helpful AI assistant tasked with summarizing conversations.»).
Патч 2.1.88 на компакцию для станка мёртв. Отдельно: думание в компакции 2.1.233
нативно гасится (thinkingConfig в бандле есть); главный выигрыш компакции — не думание,
а снижение повторов/объёма контекста.
