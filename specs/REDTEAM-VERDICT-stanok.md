# RED-TEAM VERDICT — stanok

Роль: красная команда. Вход: `REDTEAM-BRIEF-stanok.md`, `AUDIT-stanok-source-crutches.md`, код.

## 0. Тезис

Машина обросла bespoke-механизмами, потому что **изоляция и политика собраны руками**, хотя
claude-code несёт их **нативно**. Архитектурно верно — **native-first**: конфигурировать нативный
sandbox (FS-права + сетевой allow-list), нативные хуки и нативный транскрипт, а bespoke-слой
(`bwrap`-руками, хуки-замены, файловая TDD-машина, тройной сток телеметрии) убрать. Ядро машины
сжимается до **цикла сессии + одной команды-вердикта**. Docker (идея ОПЕРАТОРА) — опциональная
внешняя граница, не первая линия.

## 1. Неснижаемое ядро (обязано остаться)

1. **Session** — один непрерывный `ClaudeSDKClient`, append-only (KV). Не трогать.
2. **Verdict** — выполнить ОДНУ объявленную проектом команду проверки; `rc` = вердикт.
3. **Role** — системная роль машины (языко-нейтральная).
4. **Result** — типизированный `summary.json`.

Всё прочее ниже — кандидаты на удаление/перенос.

## 2. Решения

### D1. Граница — НАТИВНАЯ, а не собранная руками (поправка к моему `--network none`)
Факт из сорсов 2.1.88 (`source/src/utils/sandbox/sandbox-adapter.ts`,
`source/src/entrypoints/sandboxTypes.ts`): claude-code **сам несёт песочницу**
(`@anthropic-ai/sandbox-runtime`):
- `sandbox.enabled`, `sandbox.failIfUnavailable` — жёсткий гейт;
- `sandbox.network.allowedDomains` / `deniedDomains` / `allowLocalBinding` / `httpProxyPort` —
  **сетевой allow-list по домену**;
- `sandbox.filesystem.allowWrite / denyWrite / denyRead / allowRead`;
- `sandbox.autoAllowBashIfSandboxed`, `allowUnsandboxedCommands: false`;
- наружу: `SandboxViolationStore`, `annotateStderrWithSandboxFailures` — **нативная телеметрия нарушений**;
- Linux: bubblewrap + socat.

**`--network none` был моей ошибкой** и вреден. Ответ на эндпоинт: не `none`, а
`allowedDomains: ["192.168.8.131"]` (+ proxy, если нужен) — эндпоинт доступен, остальной egress
режется. Именно это и требуется, нативно.

Следствие: `sandbox-run.sh` (124 строки ручного bwrap) **дублирует нативное** → конфигурируем
`sandbox.*` в `.claude/settings.stanok.json`. Бонус — снимается языковая привязка (рантайм проекта
живёт на хосте, как сейчас).

**Зависимости.** Ставятся штатно (host `.venv`, как сегодня). Если рантайму нужен `pip`/`npm` —
его индекс добавляется в `allowedDomains` **или** зависимости пред-установлены; иначе egress закрыт.
Явный выбор, а не `none`.

**ПРЕКОНДИШЕН (блокирует D1/D4).** На Linux нужны `bubblewrap` + **`socat`**; на хосте `socat`
**MISSING** (есть только `bwrap`). При `sandbox.enabled: true` и нехватке зависимостей команды
бегут **БЕЗ песочницы**, если не стоит `sandbox.failIfUnavailable: true`
(`sandboxTypes.ts:95-103`, `sandbox-adapter.ts:562-591`, фикс #34044). Порядок: поставить `socat`
→ `failIfUnavailable: true` → проверить → и только потом выбрасывать `sandbox-run.sh`.

**Docker-упаковка (идея ОПЕРАТОРА).** Как *внешняя* граница она даёт герметичный rootfs и
воспроизводимость, но нативный sandbox уже закрывает периметр per-command. Значит контейнер —
опционален и несёт сложность (сеть/депы из вопросов оператора). Рекомендация: сначала нативный
sandbox; контейнер — только если нужна воспроизводимость рантайма.

### D2. TDD-лок → фазовая дисциплина ОС (вместо файловой машины состояний)
Инвариант, который реально нужен: «после написания тестов агент не может ослабить спеку». Это
ОС-факт, а не хеш.
- Фаза 1: `tests/` writable → агент пишет тесты; гейт: прогон = RED.
- Заморозка: раннер host-side делает `tests/` read-only **между ходами** (в контейнере — второй
  `docker run` с `tests` RO). KV сохраняется: сессия одна, ходы контролирует раннер.
- Фаза 2: `src/` writable, `tests` RO; гейт: прогон = GREEN.
- Удаляется: `hooks/verifier.sh` (156), `hooks/test-lock.sh` (57), `.stanok-locks/*`, `tdd_gate()`
  (`stanok.py:309-342`), тройной ключ лока, ветки TAMPERING/TAUTOLOGY.
- Почему сильнее: монт сильнее хеш-детекта — ослабить спеку **невозможно**, а не «поймается».
  Это же снимает CC-059-ядро: лок больше не превращает плохой тест в костыль в `src/` (`AUDIT` C11).

### D3. Один раннер-вердикт, языко-слепой
Машина зовёт **объявленную проектом команду проверки** (тот же путь, что у агента). Удаляет три
раннера (`verifier.sh:90`, `stanok.py:280`, `run.sh:47`) → уходит недетерминизм rc=124 vs rc=0
(`AUDIT` B5), глоб `*.test.js` (`stanok.py:294`), `node`-литералы, `run.sh` node.
Контент: не «формат манифеста», а **исполняемая точка входа проекта** (её даёт образ/репо).

### D4. Политика → нативные права, а не bespoke-хуки
- `hooks/read-guard.sh` (55) → `sandbox.filesystem.denyRead` + правила `Read(...)`. Оговорка:
  **глобы на Linux не поддерживаются** (bubblewrap) — политика префиксами/`allowRead`; проверить,
  что Grep/Glob тоже чтят (хук покрывал Read|Grep|Glob).
- `hooks/bash-gate.sh` (35) → правила `Bash(...)` allow/deny. **НЕ `autoAllowBashIfSandboxed`** — тот
  делает обратное (авто-разрешает любой Bash под песочницей, снимает подтверждения), тогда как
  bash-gate *ограничивал* до одной команды. Это и смена политики: «только run.sh» → «любой Bash, но
  в песочнице» — решение оператора.
- `hooks/malware-scan.sh` (88) — при закрытом egress (только эндпоинт), отсутствии секретов и
  нативном sandbox exfil-вектор закрыт, скан JS-only и дорог (~5-6 форков/запись, `AUDIT` D18).
  Оговорка: он частично прикрывал код, исполняемый позже на ХОСТЕ после коммита. **Рекомендация:
  удалить — но это SEC-решение оператора** (его SEC-03), не «бессмысленно».

### D8. Наблюдаемость: «что станок сломал и как»
Сущность, которую машине дают ломать, — **одноразовая копия workspace** (+ её рантайм).
Наблюдаемость — три нативных трейса, без bespoke-кода:
1. **git diff workspace** — *что* изменено/сломано (оператор коммитит, дерево — копия).
2. **`SandboxViolationStore`** — *что пыталась* сделать и было срезано (FS/сеть), нативно.
3. **Нативный транскрипт сессии** `~/.claude/projects/<slug>/<session-id>.jsonl` — *как* (все tool-calls).
4. Плюс нативные хуки (PostToolUse) — структурированные события, если нужен свой формат.

Следствие: bespoke-тройной сток (`events.jsonl` + `session-*.jsonl` + `launcher.stdout.log`)
дублирует транскрипт → читаем нативное, свой сток убираем.

### D5. Случайная сложность в раннере — вырезать
Мёртвый MALWARE-гейт `_pending_malware_flags` (`:345-354`, `:533-541`); `cmd_watch` (`:843-860`) +
CLI/README `watch`; `--direct` (`:890`, `launch.sh:75,97`); двойной dirty-check (оставить один);
тройной PID (оставить маркер); 4-веточные `_extract_usage`/`_safe_json_default` → типизировано из SDK;
телеметрия в 3 стока → один. Плюс мёртвые `scripts/analyze-evidence.py`, `hooks/test-lock-dump.sh`,
`tests/_diag.test.js`, `tests/_probe.test.js`.

### D6. Дубли констант — свести к одному владельцу
Модель (settings 5× + `stanok.py:44` + 2 README, `AUDIT` B9) и список инструментов (`CURATED_TOOLS`
+ settings.allow, B8) — один владелец (`settings.stanok.json`), остальное производное. Не новый формат.

### D7. Не трогать
`run_continuous_session`/KV, порядок гейтов и rc-коды, роль супервизора и запрет чтения логов на ходу,
патч claude-code 2.1.88, сервер.

## 4. Спорные места + альтернативы

1. **Контейнер vs bwrap.** Контейнер схлопывает слой, но зависимость от docker-демона и образ-на-стек.
   Альтернатива — оставить bwrap. Перевес в пользу контейнера (и это идея оператора).
2. **Заморозка тестов монтом vs хеш-лок.** Монт сильнее, но требует, чтобы границу FS держал раннер.
   Если ремонт в одном контейнере невозможен — второй `run` фазы 2. Две сессии (ломает KV) — отклонено.
3. **Malware-scan удалять.** Trade-off безопасность/стоимость; после контейнера выгода мала.
   Если оператор хочет defence-in-depth — оставить, но сделать один языко-нейтральный набор.
4. **Точка входа проекта.** Исполняемый скрипт vs данные. Красная команда: исполняемый (языко-слепо,
   без привилегированного дефолта).

## 5. Порядок внедрения (не сломать)

1. D5/D6 — чистка мёртвого и дублей (поведение неизменно).
2. D3 — единый раннер-вердикт (снимает недетерминизм).
3. D2 — фазовая заморозка (заменяет лок-машину), прогон E2E.
4. D4 — снятие избыточных хуков.
5. D1 — контейнер (самый крупный шаг, последним, за оператором).

## 6. За оператором

исполнение с E2E-проверкой.

## 7. ЭМПИРИКА (smoke 2026-09-10) — поправки к D1

Проверено на живом claude 2.1.88 (локальная `Qwen3.8-27B-MTP`, `SRT_DEBUG=1`), sandbox
включён, один `claude -p` c `--settings` (блок `sandbox` идентичен `settings.stanok.json`).

**Что работает как заявлено:**
- sandbox стартует, в т.ч. **вложенно** внутри `sandbox-run.sh` (bwrap-в-bwrap OK);
  `failIfUnavailable` не срабатывает → команды не падают.
- `socat`+`bwrap` подняты, HTTP/SOCKS-мосты живые (лог: `Linux bridges ready`).
- egress: внешний `1.1.1.1` → **403** (лог: `No matching config rule … User denied`).
- FS: запись в `.git`, `hooks`, `.claude/settings.stanok.json` → **DENIED**; `tests/` → OK.
- endpoint `192.168.8.131:8080/props` через прокси → **200** (лог: `Allowed by config rule`).

**Три поправки, которые меняют D1:**

1. **LAN-эндпоинт из Bash по умолчанию НЕДОСТУПЕН.** Рантайм жёстко инжектит
   `NO_PROXY` со ВСЕМИ приватными диапазонами (`10/8, 172.16/12, 192.168/16, 169.254/16`,
   функция `aG8` в `cli.js`). curl для `192.168.8.131` обходит прокси → прямой egress →
   режется netns (`curl: (7) … 0 ms`). Через прокси — 200 (`Allowed by config rule`).
   Т.е. `allowedDomains:["192.168.8.131"]` **сам по себе недостаточен**; нужен сброс
   `no_proxy` в самой команде (`no_proxy= ; http_proxy=…`). Модельный трафик это не
   затрагивает: API-вызов идёт процессом claude, а не Bash-инструментом.
2. **`denyWrite` на каталог `.claude/` ломает bwrap**: `Can't create file at
   .claude/commands: Read-only file system` (sandbox сам монтирует точки под `.claude`).
   Сужать до файла: `.claude/settings.stanok.json` — тогда работает.
3. **seccomp отсутствует** в bundled-сборке (`apply-seccomp binary not found`; лог:
   `unix socket blocking disabled`). Сетевой периметр держит прокси+netns, но блокировка
   unix-сокетов выключена — нужен глобально установленный `@anthropic-ai/sandbox-runtime`
   для полной защиты.

Следствие для D1: «нативный sandbox закрывает периметр и делает Bash-эндпоинт доступным»
— верно лишь частично. Периметр держит; LAN — только через прокси, т.е. не «как раньше».
Шаг «выбросить `sandbox-run.sh`» (заморожен) дополнительно требует решения по (1) и (3).
