# SPEC-DOOM-FIRE — классический огонь DOOM в терминале (2026-10-14)

Реализация — машинными тикетами (stanok `src/`/`tests/`/`docs/`, py-стек реестра,
stdlib-only: сеть в Pod закрыта, пакетов из интернета нет). Host-side: только спека,
грилл, тикеты и финальный wrap-up (TASK-5). Очередь: 4 машинных тикета CC-262..CC-265
+ host-side wrap-up. `scripts/run.sh` существует — bootstrap не нужен.

Эталон алгоритма: классический fire-эффект id Software (DOOM, r_fire.c): heat-буфер,
источник в нижнем ряду, восходящая диффузия со случайным боковым смещением и затуханием.

## 1. Математическая модель (ядро, без I/O)

- **Heat-буфер:** прямоугольная сетка `H[y][x]`, значения `int` в диапазоне `[0, 255]`
  (0 = холодно, 255 = максимум). Размеры `W ≥ 1`, `H ≥ 1` (меньше — `ValueError`).
- **Нижний ряд (источник):** пересев каждый кадр: `H[H-1][x] = rng.randint(128, 255)`
  (классический DOOM: нижний ряд всегда горячий, нижняя граница случайная).
- **Диффузия (один шаг):** двойная буферизация (без in-place алиасинга):
  для каждой ячейки `y < H-1`:
  `src = H_prev[y+1][clamp(x + off, 0, W-1)] - decay`,
  где `off ∈ {-1, 0, 1}` (равновероятно), `decay ∈ {1, 2, 3}` (равновероятно),
  результат `max(0, src)`. Строки выше читают только строку ниже предыдущего кадра —
  порядок обхода не влияет на результат.
- **Детерминизм:** ядро принимает явный объект `random.Random` (инъекция RNG).
  Один и тот же seed + одинаковые размеры ⇒ побитово идентичная последовательность
  кадров. Ядро не импортирует `sys`, `os`, `time` — 100% чистая математика.

## 2. Палитра и рендеринг

- **Палитра:** константная таблица `FIRE_PALETTE` — 21 запись `(r,g,b)`,
  чёрный → красный → оранжевый → жёлтый → белый (канонический DOOM fire-colormap):
  `(0,0,0) (7,7,7) (31,7,7) (50,11,7) (74,17,7) (102,27,7) (134,37,7) (172,47,7)
  (206,67,7) (244,83,7) (255,103,15) (255,127,27) (255,151,39) (255,171,59)
  (255,199,79) (255,227,103) (255,255,127) (255,255,159) (255,255,199)
  (255,255,239) (255,255,255)`.
  Отображение: `idx = heat * 20 // 255` (heat 0 → индекс 0, heat 255 → индекс 20).
- **TrueColor:** цвет — SGR 38;2;r;g;b (`\x1b[38;2;…m`); сброс — `\x1b[0m`.
- **Символы:** half-block `▀` (U+2580): foreground = цвет верхней половины ячейки
  (строка y), background = цвет нижней (строка y+1) ⇒ вертикальное разрешение ×2.
  ASCII-фолбэк (для `--ascii`): градиент ` .:-=+*#%@` по heat, без half-block.
- **Сборка кадра:** кадр собирается в ОДИН строковый буфер (escape-последовательности
  + `▀`-символы + `\n`), вывод — один `write` + один `flush` на кадр. Никаких
  per-cell `print`. Escape-состояние цвета сбрасывается в конце каждой строки.

## 3. Терминальный I/O и надёжность

- **Вход в экран:** `\x1b[?1049h` (alternate buffer) + `\x1b[?25l` (скрыть курсор) —
  ровно один раз при старте интерактивного режима.
- **Выход (teardown):** `\x1b[?25h` + `\x1b[?1049l` — идемпотентный (защитный флаг,
  повторный вызов — no-op). Вызывается: штатный выход, SIGINT, SIGTERM, любое
  необработанное исключение (через `atexit`).
- **Сигналы:** SIGINT → teardown + exit 130; SIGTERM → teardown + exit 143.
  Обработчики только устанавливают флаг выхода; проверка флага — на границе кадра
  (async-signal-safe паттерн). `atexit` регистрируется один раз при инициализации
  контроллера.
- **SIGWINCH:** обработчик ставит флаг resize; на границе кадра — перевызов
  `shutil.get_terminal_size()` и перестройка буфера. Между сигналами — не читаем
  размер в цикле.
- **FPS cap:** целевой интервал `1/fps` (default 30, флаг `--fps 30..60`);
  кадр → write → `time.sleep(max(0, deadline - now))` по `time.monotonic()`.
  Пауза, а не busy-wait: CPU не 100%. Headless-режим sleep не делает.
- **Headless / CI:** флаги `--headless N --seed S [--width W --height H]`:
  N шагов модели + N кадров в байтовый вывод (`sys.stdout.buffer`, UTF-8 — явная
  кодировка, не зависит от locale Pod), без TTY, без сигналов, без sleep.
  Интерактивный режим включается только если `sys.stdout.isatty()` И НЕ headless;
  тесты интерактивный цикл не запускают никогда.
- **Крайние размеры:** `get_terminal_size` бросает `OSError`/даёт 0 → фолбэк
  `shutil.get_terminal_size()` (учитывает COLUMNS/LINES, default 80×24);
  фактический размер clamp'ится к `≥1×1`; ядро при `W<1 or H<1` — `ValueError`.

## 5. Приёмка (по компонентам)

- **Core:** детерминизм по seed (два прогона → идентичные кадры); heat никогда не
  выходит за `[0,255]`; нижний ряд после шага ∈ [128,255]; значения строго
  не возрастают по направлению вверх (статистический инвариант: максимум строки y
  ≤ максимум строки y+1 до пересева — проверяется на фиксированном seed);
  `W=1`/`H=1` работают; `ValueError` при 0/отрицательных.
- **Palette:** таблица из 21 записи зафиксирована тестом; `heat=0 → (0,0,0)`,
  `heat=255 → (255,255,255)`; кадр = ровно одна строка на пару строк поля + `\n`;
  все escape-последовательности корректны; ASCII-режим не содержит U+2580.
- **Terminal:** setup/teardown выдают точные escape-последовательности в fake-stream;
  идемпотентность teardown; SIGINT/SIGTERM-обработчики (вызов напрямую) ставят
  флаг и exit-код; teardown зарегистрирован в atexit.
- **CLI/headless:** `python3 src/doomfire.py --headless 3 --seed 42 --width 8
  --height 4` → идентичный вывод при повторном запуске (subprocess-тест);
  интерактивный цикл не стартует при импорте модуля; `--headless` не обращается
  к TTY и не спит.
- **Общее:** `scripts/run.sh test --all` зелёный целиком (существующие тесты не
  затронуты); doctor rc=0; `docs/doomfire.md` — контракты модулей.

## 6. Grill Findings & Mitigations (самогрилл, 2026-10-14)

1. **Производительность stdout.** Оценка: 80×24 half-block-ячеек ≈ 1920 ячеек ×
   ~24 байт escape ≈ 46 KB/кадр → 30 FPS ≈ 1.4 MB/s — нормально для терминала,
   но per-cell `print` убил бы это flush-ами. **Митигация:** один `write`+`flush`
   на кадр (п.2); курсор/alternate — один раз на сессию, не в кадре.
2. **CI без TTY.** `isatty()==False` в Pod-верификаторе. **Митигация:** ядро и
   палитра не знают про терминал; контроллер принимает injected stream; CLI-тест
   идёт через `--headless` (subprocess), интерактивный цикл в тестах не вызывается.
3. **Крэш-сейфти.** Необработанное исключение: `atexit` выполняется при любом
   штатном завершении интерпретатора (включая uncaught) → teardown сработает;
   идемпотентный teardown не даст двойного вывода. SIGINT/SIGTERM — свои обработчики
   (не полагаемся на KeyboardInterrupt-путь).
4. **UTF-8/locale.** `▀` в Pod может упереться в POSIX-locale. **Митигация:**
   вывод через `sys.stdout.buffer.write(frame.encode("utf-8"))` — явная кодировка.
5. **1×1 / 0×0.** Ядро: `ValueError` при <1; терминал: clamp к ≥1 и фолбэк
   `shutil.get_terminal_size()`; CLI headless принимает явные `--width/--height`.
6. **SIGWINCH гонка.** Чтение размера из сигнального обработчика — источник
   рваных кадров. **Митигация:** флаг + обработка на границе кадра.
7. **Недетерминированные тесты.** Модульный RNG (`random.choice` глобально) делает
   тесты хрупкими. **Митигация:** явная инъекция `random.Random(seed)` во все
   функции ядра; глобальный RNG не используется.
8. **Висящий интерактивный цикл в верификаторе.** `run.sh test --all` не должен
   никогда запустить бесконечный цикл. **Митигация:** `__main__`-guard; импорт
   безопасен; headless конечен (N шагов).
9. **Импорт stdlib-рисков.** termios/curses НЕ используются (raw mode не нужен —
   ввода с клавиатуры нет); только `sys/os/time/signal/random/argparse/shutil/io` —
   гарантированно в image (bookworm python3).
10. **W12/реестр.** Тесты только `tests/*_test.py` (py-регистр их заявляет);
    новых top-level путей нет (всё под `src/`, `tests/`, `docs/`) — rc=13/27 не
    возможны по конструкции.

## 7. Остаточные ограничения

- PSA/G1-ресурсы: интерактивный демо-режим — ручной запуск оператором host-side
  (`python3 stanok/src/doomfire.py`); в Pod он не запускается верификатором.
- Палитра TrueColor: терминалы без TrueColor получат мусор; `--ascii` — фолбэк.
- Модель — канонический упрощённый DOOM-fire (без smoke/spark-слоёв).
- Тикеты CC-262..265 открываются только после подтверждения оператором этой спеки.
