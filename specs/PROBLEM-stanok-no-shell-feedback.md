# PROBLEM — у модели на станке нет shell-обратной связи (архитектурный вопрос, решение завтра)

Статус: **сформулировано, решение отложено оператором на 2026-09-01.**
Дата фиксации: 2026-08-31. Источник: прогоны `tetris-029` / `tetris-029-retry1`
(4 попытки), `specs/STATUS.md` (red-team-аудит 5-часового прогона), `stanok/CLAUDE.md`.

## Симптом (факты)

- Тикет 029: модель написала `Buffer.from('\x1b[D']` (лишняя скобка) в
  `tests/tetris/ui.test.js:526`. `node --check` падает. Верификатор (в конце
  попытки) → FAIL. **4 попытки (2 прогона) воспроизвели один и тот же артефакт.**
  Попытка 1 прогона 1 = 2483s (~41 мин) — сгорели на артефакт в одной строке.
- Модель **не могла поймать ошибку сама**: у неё нет Bash (CLAUDE.md станка:
  «Read, Write, Edit, Grep, Glob, WebFetch + Agent… Bash/exec/WebSearch нет»).
  Единственный синтаксический гейт — verifier после всей попытки.
- Итог: ручной доводчик оператора (разрешён вручную): `node --check` +
  `node --test` + коммит. ui 26/26, game 14/14.

## Корень (механика)

Модель кодит **вслепую**: нет цикла «написал → прогнал → увидел результат».
Все артефакты, которые ловятся исполнителем/интерпретатором (синтаксис,
runtime-ошибки, тайминги тестов), обнаруживаются только внешним верификатором
в конце попытки → весь прогон = одна попытка → ретрай = новый полный прогон
с тем же FAIL-контекстом. Это и есть «экономика ретраев» из red-team-аудита:
68% времени 5-часового прогона = ретраи после FAIL.

`node --check` + `node --test` — **частный случай**, не решение. Обобщение:
модели нужен **инструмент наблюдения за своим кодом** (исполнение в
песочнице), а не отдельная команда.

## Ограничение, которое нельзя ломать

Запрет Bash в CLAUDE.md станка — **safety-барьер**: модель не может сделать
деструктив вне `src/tests/docs` (protected-каталоги, `.git`, hooks, evidence,
корень репо). Убрать запрет целиком = потерять барьер. Требования к решению:
обратная связь **без** потери барьера.

## Кандидаты (решение завтра)

1. **Docker-песочница с bash** (предложение оператора): контейнер с node,
   запись только в `src/tests/docs`, без сети/привилегий; модель получает
   Bash **внутри** контейнера. Барьер = изоляция контейнера, а не запрет
   инструмента. Модель сама строит цикл «написал → прогнал → увидел».
   Открытые вопросы: (а) как прогнать PostToolUse-хуки (verifier/malware-scan)
   на правки внутри контейнера — хуки живут на хосте; (б) стоимость image/
   старта на попытку; (в) как сохранить test-lock (`.stanok-locks/`) при
   правках тестов через Bash-обходной путь (сейчас lock — на уровне tool-гейта
   Write/Edit; Bash-запись обходит его — нужен отдельный гейт).
2. **PostToolUse-автопрогон** (минимальный): после каждого Write/Edit в
   `tests/*.test.js` хук сам гоняет `node --check` (дёшево, синтаксис) и
   возвращает модели ошибку. Тесты целиком — только verifier. Лечит частный
   случай, не даёт модели общей обратной связи.
3. **Гибрид**: 2 как быстрая защита + 1 как полноценная обратная связь.

## Критерии решения (завтра)

- Модель видит результат исполнения **до** финального отчёта, не после.
- Protected-каталоги и `.git` остаются недосягаемыми (тот же барьер, что сейчас).
- Test-lock не обходится через Bash.
- Стоимость попытки не растёт критично (измерить: время старта песочницы vs
  экономия на ретраях; базовая линия — 41 мин на артефакт одной строки).
- Не ломает существующие прогоны (A/B: один тикет до/после, метрики —
  tool_use-циклы, доля холостых Read, время до PASS).
