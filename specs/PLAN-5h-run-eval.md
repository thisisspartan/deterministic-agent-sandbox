## Фазы

### Ф0. Верификация диагноза — ✅ сделано (2026-08-31)
Факты выше; red-team поправлен (HEADLESS-STOP не причина, SIGTERM упущен, «6 попыток» = 4).

### Ф1. Baseline-метрики (без изменений кода)
1. Зафиксировать существующие `summary.json` 018–023 как baseline-датасет (elapsed_s, rc, probe,
   cloud_calls, попытки из launcher.stdout.log).
2. Мелкая инструментация (в Ф2, НЕ сейчас): таймстемпы к `--- попытка N ---` (start/end, duration_s)
   → `summary.json` поле `attempts: [{id, duration_s, verify_ok, vfail_head}]`.
3. Метрики: (а) время/попытка, (б) попытки-до-PASS, (в) доля попыток, убитых hang/timeout,
   (г) cloud/malware эскалации, (д) токены/шаги на попытку (если доступно из сессии).
   Критерий сравнения: тот же тикет-набор → суммарно ≤ 2.5ч при той же модели.

### Ф2. Фиксы (по согласованию; низкий/средний риск)
- **A. Verifier**: `node <t>` → `node --test --test-force-exit <t>` (убивает таймерный hang; exit-коды верные).
- **B. Malware-скан**: spawn/fork флагать только при контексте `child_process`/`require(...)`.
- **C. HEADLESS-STOP лог** (1043): убрать «деливераблы не созданы» (вводит в заблуждение при реальном failing-тесте).
- **D. launch.sh:16-17** + `--no-cloud default`: оператор решил **выключить облако по умолчанию**.
  Синхронизировать doc и код. (Пометить риск: DEFECT-ловля 019/022 уйдёт — осознанное решение.)
- **E. Per-attempt timeout**: `STANOK_ATTEMPT_TIMEOUT_S` (default 0 = выкл, поведение не меняется);
  `_stall_watchdog` при ненулевом значении эскалирует warn → kill.
- **F. Инструментация попыток** (таймстемпы, метрика Ф1.2).

- Re-run representative-тикетов: **022** (таймерный hang → должен пройти с 1-й попытки) и **021**
